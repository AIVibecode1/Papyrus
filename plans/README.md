## Findings considered and rejected

- **Add vitest to pre-commit hooks**: not worth doing — CI runs the full
  suite on every push/PR, and the pre-commit stays fast by design
  (typecheck + lint + format only).
- **Move pdf.js extraction/rendering to a dedicated worker**: rejected
  for now — the pdf.js worker is already used for parsing; the render
  path is bounded by plan 004 instead. Revisit only with measured
  evidence of a main-thread problem.
- **Dependency upgrades**: verified current as of 2026-08-03 —
  pdfjs-dist 6.2.108 and mermaid 11.16.0 are the latest published
  versions (npm registry), and mermaid 11.16.0 includes the recent
  CVE-2026-41148/41149/41150/41159 fixes. No lag to plan.
- **CSP hardening**: rejected as a plan — `"csp": null` is a documented
  design decision (README security section) because users configure
  arbitrary provider base URLs; the webview loads only local assets and
  all remote fetches go through Rust.
- **SSRF via fetch_pdf**: downgraded from a security finding to plan 006
  (P3 defense-in-depth) — no script-injection surface exists today (AI
  markdown sanitized, PDF text escaped, no remote webview content).
- **build006.log leftover in the repo root**: ignored by git; harmless —
  not worth a plan.
