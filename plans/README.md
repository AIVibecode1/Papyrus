## Findings considered and rejected

- Generic visual rewrites were rejected. The current design already has a
  coherent warm monochrome palette, bundled editorial fonts, three themes,
  RTL rules, focus states, skeletons, and semantic surfaces. The redesign
  work should target the concrete reader, trust, and settings issues rather
  than replace the product identity.
- A new paper source was not implemented directly. README names OpenAlex as a
  future source, but capability, terms, rate limits, and abstract/PDF quality
  need a bounded spike first (Plan 016).
- A full PDF worker rewrite was not proposed. The current pdf.js worker already
  handles parsing; Plan 015 first adds characterization tests around the
  existing render lifecycle, and Plan 020 requires measurements before any
  virtualization.
- CSP was not reopened as a finding: README records the deliberate `csp: null`
  tradeoff because users configure arbitrary provider base URLs and remote
  calls go through Rust. The backend audit raised it as a defense-in-depth
  concern, but it conflicts with the documented product decision and requires
  a separate compatibility/security design rather than a blind change.
- No confirmed hardcoded secret was found in the inspected files. The browser
  preview key store is intentionally memory-only and must remain non-persistent.
- Dependency staleness was not promoted to a plan. `pnpm audit --prod
--audit-level high` reported no known vulnerabilities; `cargo audit` is not
  installed in this environment, so Rust dependency status remains unverified.
- Generic dark mode, decorative AI gradients, stack migration, notifications,
  and citation-based fresh-paper ranking were rejected because the repository
  already addresses them or the curated-selection spike explicitly defers
  them.

## Audit evidence index

- Backend/security audit: DNS rebinding and response-size risks in PDF fetching;
  global AI cancellation interference; stale in-memory citation TTL; and version
  drift between package, Tauri, Cargo manifest, and Cargo.lock.
- Frontend correctness audit: stale reader opens, category backfill suppression,
  favorite persistence failure, inconsistent persisted-state validation.
- Frontend performance audit: duplicate PDF parsing, eager page acquisition,
  unbounded page/text-layer mounting, missing reader boundary integration test.
- Redesign audit: action hierarchy, reader context/progress, theme discoverability,
  provenance, settings errors, mixed RTL boundaries, and curated daily direction.

No secrets are included in this index.
